# ДЗ4. Сравнение исполнителей

`ShutdownableExecutor` объединяет `Executor` и `shutdown()`. В этой работе
`shutdown()` закрывает приём задач и ждёт завершения всех принятых задач.

- `ThreadPerTaskExecutor`: отдельный платформенный поток на задачу.
- `RoundRobinExecutor`: отдельные очереди работников, раздача по кругу.
- `WorkStealingExecutor`: своя очередь с начала, чужая с конца.
- `FixedThreadPoolExecutor`: обёртка `Executors.newFixedThreadPool`, ожидание через `awaitTermination`.

Самодельные пулы учитывают ожидающие и выполняемые задачи через `pending`;
при закрытии они завершаются только после его обнуления. Новые задачи отвергаются.
Сигнал прерывания вызывающего потока сохраняется после ожидания.

## Запуск

```powershell
java -jar WorkStealing.jar --check
java -jar WorkStealing.jar --csv benchmark.csv
java -jar WorkStealing.jar --tasks 480 --threads 6 --mean 4 --warmups 2 --repeats 5 --csv benchmark-new.csv
```

Если Java отсутствует в PATH, из этой папки:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\run.ps1 --check
powershell -NoProfile -ExecutionPolicy Bypass -File .\run.ps1 --csv benchmark.csv
```

Параметры по умолчанию: 240 задач, 6 работников в пулах, средняя сложность 4,
1 прогрев и 3 замера на случай. Исходные 100000 задач уменьшены, чтобы запуск
ThreadPerTask не создавал чрезмерное число платформенных потоков. При изменении
`--tasks` учитывай, что этот исполнитель создаёт поток для каждой задачи.

Каждое из распределений UNIFORM, PERIODIC и PARETO нормируется до одинаковой
суммарной сложности. Один и тот же массив с seed=42 используется для всех
четырёх исполнителей в двух режимах. Порядок исполнителей перемешивается.
Показаны медианы. В CSV сохранены все повторы, параметры и число завершённых задач.

SLEEP: сложность - миллисекунды ожидания. CPU: `blackHole(difficulty)` делает
ровно `200000*difficulty` шагов смешивания целых чисел, результат записывается
в volatile-поле для защиты от удаления вычислений JIT. Это O(difficulty),
а не искусственное ожидание заданного числа миллисекунд.

Полное время включает конструктор, подачу и завершение задач. Время подачи
включает конструктор и вызовы execute; задачи могут уже выполняться в этот период.
Генерация задач, печать и запись CSV находятся вне интервала замера.
После каждого запуска проверяются завершение всех задач и отсутствие ошибок.

## Результаты

Замеры 08.10.2026: Intel i5-11400F (6 физических / 12 логических ядер),
Windows 11, Temurin 21.0.12.1. Медианы полного времени в мс:

| Режим / распределение | ThreadPerTask | RoundRobin | WorkStealing | FixedPool |
|---|---:|---:|---:|---:|
| SLEEP / UNIFORM | 27.898 | 235.460 | 206.310 | 196.179 |
| SLEEP / PERIODIC | 41.538 | 991.292 | 178.648 | 174.741 |
| SLEEP / PARETO | 288.391 | 428.434 | 412.321 | 398.057 |
| CPU / UNIFORM | 36.893 | 74.598 | 63.672 | 54.553 |
| CPU / PERIODIC | 46.688 | 324.747 | 64.681 | 56.391 |
| CPU / PARETO | 114.519 | 133.078 | 133.137 | 120.448 |

PERIODIC кладёт тяжёлые задачи в одну очередь RoundRobin. Общая очередь FixedPool
и кража задач устраняют перекос. FixedPool оказался самым быстрым из трёх пулов
в этой серии. ThreadPerTask может использовать больше потоков, чем пул из шести,
поэтому его хорошие результаты на 240 задачах не доказывают масштабируемость.
Длинная задача PARETO остаётся неделимой и может определять время всего запуска.
Абсолютные времена CPU и SLEEP не означают равную длительность исходной работы.

Все 72 измеряемых запуска завершили ровно по 240 задач. Проверки `--check`:
выполнение ровно один раз, повторный и пустой shutdown, отказ после shutdown,
конкурирующие execute/shutdown, сохранение прерывания, нормировка распределений.

Подробные результаты и выводы находятся в комментарии `RESULTS_BEGIN` в исходнике,
сырые данные - `benchmark.csv`, отчёт - `report.pdf`.
Это учебный стенд с тремя повторами, а не JMH; на времена влияют JIT, ОС и фоновые задачи.
